# API Specification

Placeholder for API documentation. Once endpoints are built, either:
- Maintain this as a hand-written reference (grouped by role: patient / doctor / admin / auth), or
- Generate an OpenAPI/Swagger spec from the backend framework and link/export it here

## Suggested endpoint groups
- `/auth` — login, signup, token refresh
- `/patients` — onboarding, daily check-ins, condition reports
- `/doctors` — profile, availability, patient list (post-consent)
- `/appointments` — booking, scheduling, cancellation
- `/admin` — doctor code issuance, platform management
- `/chatbot` — visitor chatbot queries
